# 02 · 制作设定与连续性

## 输入

当前采用故事、画幅与风格、已有参考和修订要求。故事尚未获采用时可做草案，但必须标记 draft；下游不把它冒充定稿。

## 先做蓝图，再细化相关资产

先列全局风格、故事阶段、人物/场景/关键道具清单，再按本次镜头涉及的资产细化。短项目可以一次交付；长项目分批，始终沿用同一清单和编号，不让每批重新命名。

### 三层区分

1. **身份**：姓名、关系、稳定辨识特征，不因机位变化改变身份。
2. **造型 look**：发型、服装、配色、鞋和配饰，一套明确方案；不要用“蓝或灰任选”代替可执行设定。
3. **状态 state**：故事发生后的变化，如湿衣、道具破损、屏幕内容或场景布局。状态不能凭离场自动恢复，常态也不等于每次出现的默认状态。

只在对白中提及的角色标为 `text-only`；无需制作视觉造型。不把每个普通背景元素都扩成独立道具；会影响辨识、动作、证据、内容变化或连续性的对象才需要追踪。

### 事实与设计来源

原文明确的年龄、关系、穿着、物件位置、状态变化使用 `story` 来源和当前正文的逐字引文。原文没给的普通视觉细节可用 `design` 来源与理由补全，不逐个向用户问颜色。字段混有两类依据时分开说明，不用一个“设计补充”标签盖住所有原文事实。

真正的问题只包括不能在保留事实和用户约束的前提下解决的决定；冲突要列出相互抵触的具体事实。首次设计本身不是冲突。修改身份、关系、明确年龄或结局不能冒充美术补全。

### 时间、造型与状态覆盖

记录现场故事阶段，只有需要画内回忆/照片时另列 depiction 阶段。状态的 `phaseIds` 允许覆盖多个不连续阶段；空数组表示无额外限制，不用它掩盖已知剧情边界。同一阶段可允许变化前后两种状态，实际镜头按发生顺序选择。

沿故事检查：首次出现状态 → 每次变化 → 最后出现状态。不要只保留变化后的状态，导致早期镜头无合法选择。`allowedLookIds` 约束状态可搭配的造型。

### 照片、屏幕与画内人物

道具的 `depictedSubjects` 绑定画内人物的 asset/look/state 和 depiction 阶段，与现场人物分开。屏幕某状态临时显示合照时只挂该状态，不挂成永久常态。

状态省略 `depictedSubjects` 表示继承；`[]` 表示明确清空；非空数组完整替换，不与常态合并。覆盖内容时写 `contentChange` 与事件依据。照片里的过去形象不会让现场人物突然年轻，也不能凭画内人物自动给现场加人。

## 输出与检查

写 `production.json`：视觉风格、阶段、资产、造型、状态和来源；固定 ID 供分镜引用。初版不要直接生图。

修订只改受影响字段，保留稳定 ID、历史版本及未受影响资产。检查事实/设计分离、状态覆盖、画内与现场分离，并指出受影响镜头。具体字段见 [project-format.md](project-format.md)。
