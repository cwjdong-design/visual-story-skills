# 使用指南

## 先规划，不默认生图

把完整 skill 文件夹导入你的 Agent，提供原文与目标即可。先交付诊断和制作资料，只有用户明确允许并提供实际工具后才进入生成。缺少工具时，提供可复制到画布的镜头提示词也是有效交付。

## 创建项目

将技能内 `assets/project-template/` 复制到自己的私人工作目录。不要覆盖已有文件。填写标题、媒介、目标与正文，按阶段完成 production.json 和 shots.json；未确认稿保持 draft。示例里的 approved 仅表示虚构示例的设定，不是替真实用户确认。

常用请求：
- “只诊断故事，不扩写，不生成图片。”
- “保留故事事实，补齐一套明确的服装与场景设计，标明哪些是补充。”
- “按已确认设定拆成8格；装不下就指出，不偷偷增格。”
- “改角色外套颜色，列出受影响镜头，先不要重新生成。”
- “我换了 Agent，读取项目并继续，不要重提未知状态任务。”

## 平台操作

用户自行登录平台，不向 Agent 聊天粘贴密码或公开密钥。让 Agent 先读取可用工具的说明，再依据平台适配模板记录能力。只有真实可调用的操作才进入执行计划。平台不支持的功能降级、交用户手动做或请求换工具，不默认购买服务。

## 校验和故障

从下载的技能位置运行 `python scripts/validate_project.py <项目目录>`；脚本不调用网络或模型。错误码为0表示可检查的完整性通过，1表示发现错误，2表示命令用法不正确。`--json` 输出机器可读结果。

典型错误：源文引用不是逐字摘录、镜头指向未定义造型、选了不适用的阶段、上游已更新但分镜依赖旧版、重复重试未知任务。修复真实资料与引用，不是删掉证据或伪造成功。

## 不同 Agent 的边界

本版不承诺任何特定产品的自动安装路径或工具协议。目录型 Skill 可导入；其他环境可显式读取入口和相对引用。只有聊天能力的 Agent 可在回复中输出文件内容，但不能声称已落盘。可用性取决于上下文容量、文件工具和画布工具，兼容结果应通过真实测试记录。
